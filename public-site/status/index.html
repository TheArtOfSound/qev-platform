Why test counts differ

The components are different codebases with different suites, not “failed tests missing from the homepage.” Each suite covers only its own component:

  • CLI npm package — small focused suite for the published package only. Run it yourself: qev self-test, or node --test test/*.test.js in the package.
  • qev-platform — separate Vitest monorepo for the commercial gateway. Run it yourself: pnpm test in qev-platform.
  • Desktop / mobile apps — Rust/Tauri build pipeline in qev-desktop. Its CI runs cargo test but does not publish a case total.
  • Browser vault — in-page crypto self-test only; no separate published suite.

Never merge these into one “QEV has N tests” claim, and never add counts across components. A count is meaningless unless the component is named.

What it takes to publish a count here
A number goes on this page only when all of the following exist:
  • a named component and the exact commit the run was made from;
  • a command a reader can run to reproduce it, or a publicly readable CI run whose output shows the total;
  • the pass/fail/skipped breakdown, not just the passing total;
  • a link to that run or command on this page, next to the number.
No number is published on the strength of another page saying it. Where those conditions are not met, this page says “no count published” — which is the current state for the desktop pipeline, the browser vault, and the product demo that is no longer on this host.
