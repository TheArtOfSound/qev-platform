# QEV Release Gates

## Gate A — Public preview honesty

Required before further promotion:

- One product hierarchy and naming system.
- One generated version and test-status page.
- Correct CLI package name everywhere.
- Remove or qualify unsupported absolute claims.
- Explain relay/network behavior precisely.
- Fix or server-render the site-integrity record.
- Publish binary hashes and source/build relationship.
- Label connector platform capabilities as planned until built.

## Gate B — Synthetic platform test

Required before AH Crap historical data:

- Installable gateway.
- Durable queue and workflow state.
- CloudEvents-aligned QEV event contract.
- Canonical JSON hashing/signing.
- Evidence Bundle V1.
- Asymmetric package signature.
- Generic signed webhook or OTLP receiver.
- Watched-folder/mobile upload input.
- Evidence-gap engine.
- Setup wizard.
- Local encrypted storage.
- Backup and restore.
- Independent verifier.
- Synthetic Field Service flow.
- Failure-injection suite.

## Gate C — Historical-data test

Required before shadow mode:

- Redacted historical AH Crap jobs can be imported.
- Exact job correlation works.
- Photos and documents hash correctly.
- Customer and internal package separation works.
- Package review answers the defined dispute questions.
- Restore to another machine succeeds.
- No secrets or customer plaintext enter support logs.
- Accessibility blockers are resolved.

## Gate D — Live shadow mode

Required before automatic sealing:

- Connectors run for a defined period without silent drops.
- Duplicate/out-of-order/retry tests pass.
- Missing evidence and outages are visible.
- Manual correction rate is measured.
- Added time per job is acceptable.
- Normal AH Crap workflow remains authoritative.
- Incident and rollback procedures are tested.

## Gate E — Limited live automation

Required before gate mode or outside customers:

- Automatic package completion succeeds reliably.
- Key recovery and recipient access are tested.
- Signed installers and updates are in place.
- Connector certification suite passes.
- External application security review is complete.
- Critical findings are remediated.
- Terms, privacy, retention, and customer-responsibility documents exist.

## Gate F — QEV Protected Workflow badge

Required before issuing the badge:

- Exact workflow scope published.
- Continuous checks implemented.
- Public signed certificate and revocation status implemented.
- Backup/recovery, key policy, connector health, access review, and tamper tests pass.
- Badge suspension works automatically.
- Independent assessment is clearly distinguished from Qira's own configuration check.
